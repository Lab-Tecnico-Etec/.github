# Como contribuir

Obrigado por contribuir com o Lab Técnico ETEC. Queremos que os projetos sejam acessíveis para estudantes em diferentes níveis de experiência.

## Antes de começar

1. Leia o README e as instruções específicas do repositório.
2. Confira as issues abertas e procure evitar trabalho duplicado.
3. Para mudanças grandes, abra uma issue antes de implementar.
4. Confirme que você tem autorização para publicar o código, imagens, dados e materiais utilizados.

## Fluxo recomendado

1. Crie uma issue descrevendo problema, objetivo ou melhoria.
2. Crie uma branch com nome claro, por exemplo `feat/login`, `fix/validacao-formulario` ou `docs/instalacao`.
3. Faça mudanças pequenas e focadas.
4. Execute os testes disponíveis e registre limitações conhecidas.
5. Abra um Pull Request com contexto, alterações, testes e capturas de tela quando forem úteis.
6. Aguarde revisão e responda aos comentários antes do merge.

## Padrões mínimos

- Use nomes claros e consistentes.
- Documente instalação, configuração e execução.
- Nunca envie senhas, tokens, chaves privadas, dados pessoais ou arquivos `.env`.
- Não inclua dependências, imagens ou código de terceiros sem verificar licença e atribuição.
- Preserve o trabalho existente; mudanças destrutivas precisam de justificativa e aprovação.
- Respeite a autoria e não publique projeto individual na organização sem autorização explícita.

## Pull Requests

Um PR deve explicar:
- O que mudou e por quê.
- Como testar.
- Resultado dos testes.
- Riscos, limitações ou migrações necessárias.
- Issue relacionada, se houver.

Contribuições devem ser respeitosas, inclusivas e orientadas ao aprendizado. Consulte também o [Código de Conduta](CODE_OF_CONDUCT.md) e a [Política de Segurança](SECURITY.md).
